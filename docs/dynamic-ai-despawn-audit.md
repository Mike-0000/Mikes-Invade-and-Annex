# Dynamic AI despawn audit — 2026-09-17

The reported AO dependence is not yet established: the user's sample contains both successful and unsuccessful departures, without confirmed AO names or budget settings. These findings come from source inspection. They do not identify which branch ran on the affected server.

## Corrected in this change

1. **Budget eviction could starve indefinitely behind blocked distant groups.** `IA_DynamicAIBudgetController.Service` selected the farthest group afresh each tick and discarded its local refusal list. A refusal consuming the one-millisecond search allowance (or the whole worker allowance) prevented later groups from ever being attempted. Even an already empty, very distant group remained a candidate. The refusal list now survives across ticks until a complete sweep finishes; successful removals still prefer the farthest group. Allocation replans do not restart the sweep. Regression: a blocked group at 5 km must not prevent four removals from another group at 3 km, and the blocked group must receive another chance on the next sweep.
2. **Civilians trapped the budget-0/OFF handoff.** The controller considered itself active whenever civilian caches existed. After the military budget ledger drained, the dispatcher continued calling the budget controller, leaving military distance-only scans unreachable. It also continued attempting civilian caching during OFF. Only an unfinished military budget ledger now holds the drain active; civilian distance work runs in this controller only with a positive budget. The ordinary dispatcher resumes after the drain. Regression: a civilian-only registry cannot keep a zero-budget controller active or receive a fresh cache attempt from it.
3. **An emplacement transaction could veto itself after ejecting its crew.** `CanRemoveUnit` rejected every soldier while its cache participated in an occupancy transaction. Before ejection, the seated-candidate branch avoided that rejection; after ejection, `Describe` interpreted it as protected demand. A census during the quiescence/commit window could therefore raise allocation above zero, causing the occupancy worker to abort and remount. The transaction lock now blocks the infantry deletion worker directly, without turning healthy ejected soldiers into protected allocation. Close distance, minimum live time, ownership, membership, health and role protection still apply. Actual native ejection/remount requires a gameplay check.

## Remaining gates and failure paths

| Path | Why AI can remain physical | What distance changes |
| --- | --- | --- |
| Registration / ownership | Only I&A area-owned groups with a live native group are registered. Military groups enter through `AddMilitaryGroup`; current dynamic bases, HVT/guards, elite patrols, defense and QRF use that path. Civilian and vehicle spawners set ownership separately. GM-placed or external-addon groups are outside this registry. The legacy `IA_AreaAttackers` spawner does not register groups, but its owner field is never assigned a new instance in the inspected code. | Nothing for an unregistered group. |
| Vehicle policy | Vehicle crews and passengers stay physical. Crew/driving/reference flags can retain this classification even when soldiers are temporarily on foot. Dumped passengers are eligible once none remain seated in a world vehicle. Vehicle groups are outside the military allocation pool. Assigned mortar-vehicle gunners (seated on their assigned tube) use this same exemption so occupancy caching cannot eject them. Mortar-pit guards on foot remain infantry. | Vehicles, mortar gunners, and their protected groups remain by design. |
| Health / status | Conscious wounds, persistent effects, missing character/controller/damage state, parenting and player possession prevent a safe snapshot. Budget mode protects affected individuals; distance-only mode rejects the whole group if one member fails. Downed deaths can be refused by external damage settings, leaving the soldier physical. | These safety gates do not expire with distance. This can make previously fought AOs behave differently from untouched AOs. |
| Initialization | Pending staggered spawns or typed-waypoint changes prevent removal. Normal callbacks clear these flags. Interrupted callbacks or script errors can leave the gates latched. | No override. Check server script errors and role status. |
| Pending vehicle seating | `_PlaceSpawnedUnitsInVehicle` returns immediately if its vehicle or crew is gone, before clearing pending-seat flags on surviving groups. Most such groups are also protected by vehicle policy. | No override for a pending-seat flag. |
| Airborne groups | `m_bAirborneDrop` blocks both modes. Release depends on flight-completion bookkeeping. `OnAirborneJumperFinished` ignores a character no longer in its native group, and the HALO director cannot emit a character callback after that entity is gone. A transfer/deletion during flight can leave the counter and role latched on survivors. This is a source-supported edge case, not a reproduced cause in the user's session. | No override while marked airborne. |
| Budget timing | Fresh soldiers are protected for minimum live time, then allocation reductions wait for the eviction delay. Capture seeds and already admitted restore retries retain their rules. Plans older than five seconds prevent optional restoration and eviction; a very slow census can produce long gaps. | Beyond outer retention, healthy unprotected groups should receive zero allocation, then shed soldiers after the delays. |
| Combat | Recent combat blocks budget eviction only inside wake range, with hard cap off and shared cost below target. Distance-only departure already ignores distant danger/selected targets. | All-player departure beyond wake/cache removes combat as a cause. Old AI-versus-AI combat alone does not explain a far squad remaining. |
| Worker load | Mandatory restores run first; long native calls can consume an entire tick. Civilians and occupancy use remaining operation slots. Sustained higher-priority work can delay these pools. The elapsed limits are soft and cannot interrupt a native call. | Greater distance does not increase worker throughput. |
| Emplacement qualification | Requires a replicated, stationary host, healthy registered occupants, no nearby players, no positive linked-group allocation, and no pending compartment tree. The initial qualification rejects a persistent boarding waypoint before reaching the step that strips orders; stuck boarding can therefore block entry. Missing/invalid host IDs also prevent a request. | Leaving helps proximity only. |
| Emplacement ejection / rollback | Native exit can remain pending; the current worker retries without an overall transaction deadline. Host iteration restarts at the first map entry each tick, so slow early hosts can delay later ones. A wounded on-foot teammate can keep the group's allocation positive and prevent its seated members from qualifying. | Leaving does not resolve a failed native exit, health protection, or an allocation veto. |
| Mixed occupancy in distance-only mode | Caching one seated member marks the base cache cached. Remaining on-foot members of the same native group are then skipped by the ordinary whole-group scan until restoration finishes. Authored single-operator groups avoid this, but mixed native squads can expose it. | No additional departure cleanup while that cache remains partial. |
| Snapshot / resource failure | Unavailable prefab resources prevent caching. Budget failures back off for 30 seconds and can repeatedly retry the same farthest soldier; distance-only failures restart the whole-group quiet period. | No override for an unrecreatable prefab. |
| Completion / cancellation | Area shutdown retires cache records and hands surviving physical soldiers to ordinary area/garbage cleanup. They no longer participate in dynamic eviction. Live-near-player cleanup protections and corpse lifetimes are separate from the dynamic infantry target. | Inspect ordinary cleanup if the AO has already ended. |
| Player sampling | Uses every connected player's controlled entity and its world transform, with horizontal distances. It does not use an objective center or spectator camera. A GM camera miles away can coexist with a pawn near the AO; another player's pawn can also retain troops. | Every relevant pawn must leave. Vertical separation alone does not qualify. |
| What is being counted | Logical roster strength intentionally includes virtual survivors. Corpses, vehicles, external groups and the editor's independent budget can remain after managed characters disappear. | Verify actual living characters, not only mission strength or the GM percentage. |

These remaining policies and edge cases were not broadly relaxed in this patch. In particular, injured soldiers are not healed through deletion/recreation and vehicle crews are not silently opted into caching. Further changes to native occupancy or airborne ownership need targeted gameplay evidence.
